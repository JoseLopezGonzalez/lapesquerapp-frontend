# GAP-V2-109 — `buildGs1128` en creación desde previsión usa AI 3100 en vez de 3102

## Problema

`buildGs1128` (`src/components/Admin/OrdersManager/Order/OrderPallets/hooks/useOrderPallets.ts:636-651`)
construye el código GS1-128 de cada caja generada automáticamente desde la previsión del
pedido:

```ts
const formatted = w.toFixed(2).replace('.', '').padStart(6, '0');
return `(01)${gtin}(3100)${formatted}(10)${lotVal}`;
```

El peso se codifica con 2 decimales de precisión (`w.toFixed(2)`) pero se declara bajo el
Application Identifier **3100** (peso neto en kg, 0 decimales implícitos según el estándar
GS1). Es exactamente el mismo defecto ya identificado y priorizado como P0 en
**GAP-V2-078** (`usePalletBoxOperations.ts:73-88`) durante la primera pasada de este módulo:
cualquier lector GS1-128 externo estándar (cliente, transportista, carretilla elevadora)
interpretará el valor de 6 dígitos como un entero de 0 decimales, decodificando el peso real
×100 (p.ej. 12,34 kg se leería como 1234 kg).

GAP-V2-078 fue registrado con `target_files` limitado a `usePalletBoxOperations.ts` y
`gs1128Parser.js` — no cubre este archivo. La causa raíz (mismo error de AI) está duplicada
en al menos 4 archivos del proyecto (confirmado por grep de `(3100)`/`(3200)`):
`usePalletBoxOperations.ts`, `useOrderPallets.ts` (este GAP),
`useProductionInputsManager.js`, `ProductionInputsAddDialog.jsx` y `LabelSelectorSheet.jsx` —
los últimos tres fuera del módulo `pallets`, no cubiertos por esta auditoría.

## Objetivo

Todas las cajas creadas automáticamente desde la previsión de un pedido generan un GS1-128
con el AI correcto (3102 para 2 decimales de precisión, o el AI que corresponda a la
precisión real usada), de forma consistente con la corrección que se aplique en
GAP-V2-078.

## Contexto

Depende directamente de la solución elegida en GAP-V2-078 — implementar ambos con la misma
convención de AI para evitar que una corrección puntual en un archivo dejen viva la misma
inconsistencia en otro. Recomendado implementar GAP-V2-078 primero y luego aplicar el mismo
fix aquí, o extraer una función compartida `buildGs1128()` como parte de esa misma
implementación (nota de arquitectura para `code-audit-agent`/`gap-implementor`, no se pide
aquí como requisito de dominio).

## Solución propuesta

Cambiar `(3100)` por `(3102)` en la línea de construcción del GS1-128 de
`buildGs1128`, replicando exactamente el fix aplicado en GAP-V2-078. Si GAP-V2-078 extrae
una función compartida de construcción de GS1-128, usarla aquí en vez de duplicar la lógica
de nuevo.

## Criterios de aceptación

- [ ] El GS1-128 generado en `handleCreatePalletFromForecast` usa el AI correcto para la
      precisión real del peso codificado.
- [ ] Un lector GS1-128 estándar decodifica el peso real de una caja creada desde previsión
      sin necesidad de dividir entre 100.
- [ ] Consistente con la convención aplicada en GAP-V2-078 (mismo AI, misma lógica).

## Plan de validación

```text
npm run type-check
npm run lint
Verificación manual: crear un palet desde la previsión de un pedido, decodificar el GS1-128
generado con un validador GS1 estándar y confirmar que el peso coincide con el real.
```
