# GAP-V2-081 — Vincular un palet a un pedido no valida ni advierte si el producto no coincide con ninguna línea del pedido

## Problema

`editOrderId` (`src/hooks/pallets/usePalletBoxOperations.ts:497-500`) acepta cualquier
`orderId` sin ninguna comprobación relacionada con el contenido del palet:

```ts
const editOrderId = (orderId: number | string | null) => {
  if (!temporalPallet) return;
  setTemporalPallet((prev) => (prev ? { ...prev, orderId } : prev));
};
```

Tanto el selector desktop (`PalletView/index.tsx:1096-1099`) como los equivalentes mobile
(`InfoTab.tsx:82-96`, `PedidoScreen.tsx`) listan todos los `activeOrdersOptions` (pedidos
activos, sin cerrar) devueltos por `getActiveOrdersOptions()` — la única lista de pedidos
disponible para vincular no está filtrada ni acompañada de ningún aviso sobre si el producto
de las cajas del palet coincide con lo que ese pedido necesita.

Un operario puede vincular por error un palet de un producto (p. ej. "Merluza congelada H/G")
a un pedido cuyas líneas piden un producto o formato completamente distinto (p. ej. "Gambas
frescas"), y el sistema lo permite y guarda sin ninguna señal de alerta en el momento — el error
solo se detectaría más tarde, al preparar la expedición o al revisar el pedido.

## Objetivo

Al vincular un palet a un pedido, el operario recibe una advertencia clara y en el momento si
ninguno de los productos de las cajas del palet coincide con ninguna línea del pedido
seleccionado — sin bloquear necesariamente la operación (puede haber casos legítimos de
sustitución/reasignación), pero sí exigiendo una confirmación explícita en ese caso.

## Contexto

Esta pregunta está explícitamente dentro del alcance de la auditoría de dominio ("¿La
vinculación a pedido desde el palet respeta reglas de negocio razonables — unidades,
disponibilidad, formato solicitado por el cliente?"). No hay visibilidad, dentro del alcance
leído, de si el backend aplica alguna validación de coincidencia producto-pedido al guardar — si
ya existe validación backend-side, este GAP se reduce a añadir el aviso equivalente en el
frontend para dar feedback inmediato en vez de esperar un error 422 tras guardar.

**Pregunta para Jose (no asumir):** ¿existe ya una validación de backend que rechace vincular un
palet a un pedido cuyo producto no aparece en ninguna línea del pedido? Si existe, este GAP debe
limitarse a replicar esa validación como advertencia temprana en el frontend (evitando el
roundtrip de guardar → 422 → corregir). Si no existe, habría que decidir si el negocio quiere
bloquear la vinculación o solo advertir.

## Solución propuesta

- Extender `getActiveOrdersOptions()` (o un nuevo endpoint/parámetro) para incluir, junto a cada
  pedido, los IDs de producto de sus líneas — o resolver esa comprobación en el frontend a partir
  de datos ya disponibles si el pedido completo se puede consultar sin coste adicional.
- En el `Select`/`Combobox` de pedido (desktop e mobile), si el pedido seleccionado no comparte
  ningún producto con las cajas del palet, mostrar un `Alert`/badge de advertencia junto al
  selector (patrón ya usado en el propio módulo, ver `PalletLabelDialog` `Alert
  variant="destructive"`), sin bloquear el guardado salvo que Jose confirme que debe bloquearse.

## Criterios de aceptación

- [ ] Vincular un palet a un pedido cuyo producto no coincide con ninguna caja del palet muestra
      una advertencia visible antes de guardar, tanto en desktop como en mobile.
- [ ] Vincular un palet a un pedido con al menos un producto coincidente no muestra la
      advertencia.
- [ ] Un palet sin cajas (nuevo) vinculado a un pedido no dispara la advertencia (no hay nada
      que comparar todavía).
- [ ] Comportamiento confirmado con Jose respecto a bloqueo vs. advertencia antes de implementar.

## Plan de validación

```text
npm run type-check
npm run lint
Verificación manual: crear un palet con cajas de un producto, vincularlo a un pedido de un
producto distinto y confirmar que aparece la advertencia; vincularlo a un pedido con el mismo
producto y confirmar que no aparece.
```
