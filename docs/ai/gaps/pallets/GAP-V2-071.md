# GAP-V2-071 — `PalletLabelDialog` usa `useIsMobile()` sin guard para ramificar el árbol completo de render

## Problema

`PalletLabelDialog` usa el hook `useIsMobile()` (variante sin `mounted` guard) para decidir
entre dos árboles de componentes completamente distintos: en mobile monta
`MobilePalletLabelPrintTrigger` (imprime automáticamente sin diálogo visible), en desktop
monta un `Dialog` completo con vista previa de la etiqueta:

```tsx
// src/components/Admin/Pallets/PalletLabelDialog/index.tsx:12,83-94
import { useIsMobile } from '@/hooks/use-mobile';
...
const isMobile = useIsMobile();

if (isMobile) {
  return (
    <MobilePalletLabelPrintTrigger
      isOpen={isOpen}
      pallet={pallet}
      onPrint={onPrint}
      onClose={onClose}
    />
  );
}
// Desktop: dialog normal
```

`design-context.md` § Mobile Patterns exige explícitamente `useIsMobileSafe` (con
`mounted`) para cualquier renderizado condicional estructural, precisamente para evitar
hydration mismatch — nunca `useIsMobile` a secas. Esto es una recurrencia directa del
`AUDIT_RULE` PL-022 (`project-learnings.md`), que ya detectó el mismo patrón en CRM, Field
app y 15 archivos del editor de pedidos, y que pide expresamente ejecutar un grep
exhaustivo de `useIsMobile()` en cualquier auditoría — grep que en este módulo localiza
exactamente este archivo.

El riesgo concreto aquí no es solo estético: en mobile, esta rama **dispara la impresión
automáticamente en un `useEffect` con un `setTimeout(150)`** apenas se detecta
`isMobile`. Si el primer render en el servidor/cliente antes de la hidratación decide
`isMobile === false` (valor por defecto sin guard) y luego se corrige a `true` tras
hidratar, existe una ventana en la que el diálogo desktop podría montarse brevemente antes
de que la app recalcule y dispare el trigger de impresión mobile — comportamiento no
determinista que el propio patrón `useIsMobileSafe` + `mounted` está diseñado para
prevenir en toda la aplicación.

## Objetivo

`PalletLabelDialog` usa `useIsMobileSafe` con guard `mounted` para decidir su rama de
render, igual que el resto de componentes con ramificación estructural del módulo
(`PalletDialog/index.tsx`, `MobilePalletView`), eliminando el uso de `useIsMobile()` sin
guard.

## Contexto

Recurrencia de PL-022. El propio módulo Pallets ya tiene la implementación correcta como
referencia en `PalletDialog/index.tsx:61` (`const { isMobile, mounted } = useIsMobileSafe();`).

## Solución propuesta

Sustituir `import { useIsMobile } from '@/hooks/use-mobile'` por
`import { useIsMobileSafe } from '@/hooks/use-mobile'` y `const { isMobile, mounted } =
useIsMobileSafe();`. Mientras `!mounted`, no renderizar ninguna rama (o renderizar `null`)
hasta que el valor de `isMobile` esté confirmado en cliente, siguiendo el mismo patrón que
`PalletDialog/index.tsx` (`hideMobileDialogChrome`, `useMobileHeader` ya dependen de
`mounted`).

## Criterios de aceptación

- [ ] `PalletLabelDialog` importa y usa `useIsMobileSafe`, no `useIsMobile`.
- [ ] El componente no ramifica su árbol de render hasta que `mounted === true`.
- [ ] El comportamiento de impresión automática en mobile (`MobilePalletLabelPrintTrigger`)
      y el diálogo completo en desktop se mantienen sin cambios funcionales.
- [ ] No quedan otros usos de `useIsMobile()` sin guard en el módulo Pallets (verificar con
      `grep -rn "useIsMobile()" src/components/Admin/Pallets`).

## Plan de validación

```text
npm run type-check
npm run lint
grep -rn "useIsMobile()" src/components/Admin/Pallets
Verificación manual: imprimir etiqueta de palet desde mobile (debe imprimir automáticamente
sin mostrar diálogo) y desde desktop (debe mostrar el diálogo con vista previa).
```
