# GAP-V2-079 — "Peso bruto" por caja en el historial de trazabilidad es siempre igual al peso neto

## Problema

Al crear o duplicar una caja, `grossWeight` se fija siempre igual a `netWeight`, sin excepción:

```ts
// src/hooks/pallets/usePalletBoxOperations.ts:108-114 (addBox)
const boxWithId: PalletBox = {
  ...(boxWithRoundedWeight as PalletBox),
  id: uniqueId,
  new: true,
  gs1128,
  grossWeight: roundedNetWeight,   // ← siempre = netWeight, nunca neto + tara
};
```

```ts
// usePalletBoxOperations.ts:129-135 (duplicateBox)
const newBox: PalletBox = {
  ...boxToDuplicate,
  id: generateUniqueIntId(),
  new: true,
  netWeight: roundedNetWeight,   // grossWeight heredado del original, nunca recalculado
};
```

Sin embargo, `PalletTimeline/TimelineEventDetail.jsx` (usado en la pestaña "Historial" del
editor de palet) muestra ambos valores lado a lado como si fueran datos independientes y reales:

```jsx
// TimelineEventDetail.jsx:82-83
{d.netWeight != null && <span>Peso neto: {formatDecimalWeight(d.netWeight)}</span>}
{d.grossWeight != null && <span>Peso bruto: {formatDecimalWeight(d.grossWeight)}</span>}
```

```jsx
// TimelineEventDetail.jsx:475-479 (tabla de cajas del evento)
<TableCell>{box.netWeight != null ? formatDecimalWeight(box.netWeight) : '—'}</TableCell>
<TableCell>{box.grossWeight != null ? formatDecimalWeight(box.grossWeight) : '—'}</TableCell>
```

El dominio de esta empresa sí tiene un concepto real de tara por caja: el modo de creación
"promedio" (`usePalletBoxCreation.ts`, método `average`) pide explícitamente "Tara por Caja (kg)"
y la resta del peso total para calcular el neto. Es decir, el sistema sabe que una caja física
pesa más que su contenido neto — pero nunca traslada esa tara al campo `grossWeight` de la caja
resultante; `grossWeight` queda igual a `netWeight` en el 100% de los casos, para las 5 formas de
alta de caja (manual, promedio, masiva, lector, códigos GS1).

Esto hace que el historial de trazabilidad — el documento que un administrador consultaría para
auditar o reconciliar diferencias de peso con lo declarado por el cliente en un albarán — muestre
sistemáticamente "peso bruto = peso neto" para cada caja, como si el envase/caja no pesara nada.
Es un dato fabricado, no calculado, y puede inducir a error a quien lo usa para conciliar bruto
vs. neto en un despacho o una factura.

## Objetivo

El historial de trazabilidad no presenta un "peso bruto" por caja que en realidad nunca se
calcula de forma distinta al peso neto — o bien deja de mostrar ese campo, o bien el campo
`grossWeight` se calcula realmente (neto + tara conocida) cuando existe una tara aplicable.

## Contexto

Esto es distinto de la tara del palet (`palletTareWeightKg`), que sí se rastrea correctamente y
se usa para calcular un "peso bruto estimado" del conjunto del palet en `ResumenTab.tsx:22-29`
(mobile) — ese cálculo es correcto porque suma tara real + peso neto real. El problema aquí es
específico del campo `grossWeight` a nivel de **caja individual**, que nunca refleja una tara
real.

## Solución propuesta

Opción A (recomendada si no hay una tara por caja fiable en todos los casos): eliminar la
columna/campo "Peso bruto" por caja del historial de trazabilidad (`TimelineEventDetail.jsx`),
dejando el peso bruto solo a nivel de palet (donde sí es real), y eliminar el campo `grossWeight`
duplicado de `addBox`/`duplicateBox` si no tiene otro consumidor legítimo.

Opción B (si el negocio sí necesita bruto por caja): capturar/persistir la tara por caja también
en los modos de alta manual, masiva y lector (no solo en "promedio"), y calcular
`grossWeight = netWeight + taraCaja` de verdad en `addBox`/`duplicateBox`/`editBox.netWeight`.

Decisión de negocio a confirmar con Jose antes de implementar (ver pregunta en el resumen).

## Criterios de aceptación

- [ ] El historial de trazabilidad no presenta un valor de "Peso bruto" por caja idéntico al
      neto de forma sistemática y no derivada de un cálculo real.
- [ ] Si se opta por la Opción B: `grossWeight` refleja neto + tara real en todos los modos de
      alta de caja, no solo en "promedio".
- [ ] No se rompe ningún consumidor existente de `PalletBox.grossWeight` fuera del historial de
      trazabilidad (grep `grossWeight` antes de cerrar).

## Plan de validación

```text
npm run type-check
npm run lint
grep -rn "grossWeight" src/ para confirmar todos los consumidores actualizados coherentemente.
Verificación manual: crear una caja con tara conocida (modo "promedio"), abrir el historial de
trazabilidad del palet y confirmar que "Peso bruto" ya no es una copia idéntica del neto (Opción
B) o que el campo ya no aparece a nivel de caja (Opción A).
```
