# GAP-V2-106 — Asignar un palet a una posición ya ocupada no advierte ni bloquea

## Problema

El botón "+" para añadir un palet a una posición está siempre visible y habilitado,
independientemente de si la posición ya tiene palets ubicados:
`PositionPopover/index.js:73-92` (`handleAddPallet` → `openAddElementToPosition(id)`) y
`PositionSlideover/index.tsx:43-46,64-70,81-84` (`handleOnClickAddElement`) no comprueban
`isPositionFilled(id)` antes de abrir el diálogo de asignación.

`AddElementToPositionDialog/index.tsx` (líneas 66-94) llama directamente a
`assignPalletsToPosition` sin ningún chequeo de ocupación de la posición destino —
`isPositionFilled` (`src/hooks/useStorePositions.ts:177-180`) existe y se usa solo para
pintar el color de fondo de la posición en el mapa (`Position/index.tsx:41-45`), nunca como
guarda antes de confirmar una asignación.

En una pesquera/congelados, una "posición" de almacén es un espacio físico concreto (un
hueco de estantería, una casilla del mapa). Registrar dos palets en la misma posición sin
ningún aviso crea una inconsistencia entre el sistema y la realidad física: el operario que
va a esa posición físicamente puede encontrar un palet distinto al esperado, o no saber cuál
de los dos registrados está realmente ahí. Esto es un riesgo directo de trazabilidad —el
problema exacto que un módulo de almacén de congelados debe prevenir— no solo una carencia de
confirmación de UI.

## Objetivo

El sistema advierte explícitamente al usuario cuando va a asignar un palet a una posición
que ya tiene uno o más palets ubicados, y requiere una confirmación deliberada antes de
completar la asignación (salvo que el negocio confirme que una posición puede alojar
legítimamente varios palets simultáneamente, en cuyo caso el GAP se cierra como "rejected"
con esa aclaración).

## Contexto

Detectado en la auditoría de dominio de la Superficie B (movimientos de almacén) de la
segunda pasada v2 de `pallets`. Pregunta abierta para Jose: ¿una posición física del almacén
puede alojar legítimamente más de un palet a la vez (p.ej. posiciones de picking de varios
niveles), o cada posición representa un único hueco físico para un único palet? La solución
depende de esta respuesta — si la respuesta es "una posición = un único palet", el fix debe
bloquear (no solo advertir) la asignación a una posición ya ocupada.

## Solución propuesta

Si Jose confirma que cada posición aloja un único palet: bloquear la selección de una
posición ya ocupada en `AddElementToPositionDialog` (o mostrar un diálogo de confirmación
explícito indicando qué palet(s) se desplazará(n) o quedará(n) co-ubicados) antes de llamar
a `assignPalletsToPosition`. Si el negocio permite varios palets por posición: al menos
mostrar en el diálogo, antes de confirmar, qué palets ya ocupan la posición destino (hoy solo
se ve en el tab "Todos los pallets" mediante el badge de posición de cada tarjeta, no como
resumen de la posición destino).

## Criterios de aceptación

- [ ] Confirmado con Jose el modelo de negocio (una posición = un palet, o varios permitidos).
- [ ] Si aplica bloqueo: no es posible completar `assignPalletsToPosition` sobre una posición
      ocupada sin una confirmación explícita adicional.
- [ ] El diálogo de asignación muestra claramente qué ocupa ya la posición destino antes de
      confirmar.

## Plan de validación

```text
npm run type-check
npm run lint
Verificación manual: abrir una posición ya ocupada en el mapa del almacén, pulsar "+" y
confirmar que el sistema advierte/bloquea antes de asignar un palet adicional.
```
