# GAP-V2-072 — Botones de solo icono sin nombre accesible en el visor de imágenes del palet

## Problema

En el lightbox de imágenes del palet, varios botones de solo icono no exponen un nombre
accesible robusto para lectores de pantalla:

**Desktop** (`PalletImagesTab/index.tsx`, componente `Lightbox`, líneas 267-296): los
botones Descargar/Eliminar/Cerrar usan únicamente el atributo `title` como única pista de
accesibilidad, sin `aria-label`:

```tsx
<Button variant="ghost" size="icon" ... onClick={handleDownload} disabled={!src} title="Descargar">
  <Download className="h-4 w-4" />
</Button>
{canDelete && (
  <Button variant="ghost" size="icon" ... onClick={() => onDelete(attachment.id)} title="Eliminar">
    <Trash2 className="h-4 w-4" />
  </Button>
)}
<Button variant="ghost" size="icon" ... onClick={onClose} title="Cerrar">
  <X className="h-4 w-4" />
</Button>
```

`title` no es un sustituto fiable de `aria-label`: no todos los lectores de pantalla lo
exponen como nombre accesible, y no aparece en absoluto en interacción táctil (mobile).

**Mobile** (`ImagenesTab.tsx`, componente `MobileLightbox`, líneas 169-176): los mismos
botones (Eliminar y Cerrar) no tienen ni `aria-label` ni `title` — no exponen ningún nombre
accesible:

```tsx
{canDelete && (
  <Button variant="ghost" size="icon" className="h-8 w-8 text-destructive"
    onClick={() => { onDelete(attachment.id); onClose(); }}>
    <Trash2 className="h-4 w-4" />
  </Button>
)}
<Button variant="ghost" size="icon" className="h-8 w-8" onClick={onClose}>
  <X className="h-4 w-4" />
</Button>
```

Otros botones del mismo módulo sí siguen el patrón correcto (`aria-label="Cerrar"` en
`MobilePalletScreenHeader.tsx:36`, `aria-label="Eliminar caja"` en `EliminarTab.tsx:147`),
lo que confirma que es una omisión puntual del visor de imágenes, no una decisión de
diseño.

## Objetivo

Todos los botones de solo icono del visor de imágenes (desktop y mobile) exponen un
`aria-label` descriptivo, consistente con el resto del módulo.

## Contexto

Categoría a11y-responsive del audit — hallazgo específico de nombres accesibles, no
cubierto por el carril de UX general.

## Solución propuesta

- Añadir `aria-label` (además de mantener `title` donde ya exista, por el tooltip visual en
  desktop) a los botones Descargar/Eliminar/Cerrar del `Lightbox` desktop.
- Añadir `aria-label="Eliminar imagen"` y `aria-label="Cerrar"` a los botones equivalentes
  de `MobileLightbox` en `ImagenesTab.tsx`.
- Usar los mismos textos de label ya usados en el resto del módulo para consistencia
  (`"Cerrar"`, `"Eliminar imagen"`, `"Descargar"`).

## Criterios de aceptación

- [ ] Los tres botones de icono del `Lightbox` desktop (`Descargar`, `Eliminar`, `Cerrar`)
      tienen `aria-label`.
- [ ] Los dos botones de icono del `MobileLightbox` (`Eliminar`, `Cerrar`) tienen
      `aria-label`.
- [ ] No se elimina el `title` existente en desktop (se mantiene como tooltip visual
      adicional).
- [ ] Los labels usados son consistentes con el resto del módulo (mismo texto que
      `EliminarTab.tsx`/`MobilePalletScreenHeader.tsx` donde aplique un concepto
      equivalente).

## Plan de validación

```text
npm run type-check
npm run lint
Verificación manual con lector de pantalla (VoiceOver/NVDA) o inspección de accessibility
tree en DevTools: confirmar que cada botón de icono anuncia un nombre descriptivo.
```
