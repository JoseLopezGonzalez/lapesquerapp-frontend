# GAP-V2-110 — `handleCreatePalletFromForecast` no valida `quantity` positiva

## Problema

`handleCreatePalletFromForecast`
(`src/components/Admin/OrdersManager/Order/OrderPallets/hooks/useOrderPallets.ts:580-747`)
filtra las líneas de previsión a usar con:

```ts
const detailsWithBoxes = (plannedProductDetails || []).filter(
  (d) => d?.id && d?.product?.id && Number(d.boxes) > 0
);
```

Solo exige que `boxes` (número de cajas) sea positivo — no valida que `quantity` (el peso
total a repartir entre esas cajas) sea también positivo. Más abajo (líneas 663-690):

```ts
const totalQty = parseFloat(String(detail.quantity)) || 0;
...
const weightPerBox = totalQty / numBoxes;
const standardWeight = roundToTwoDecimals(weightPerBox);
```

Si `quantity` es 0 o negativo (dato inconsistente de la previsión, p.ej. por un ajuste
manual mal introducido en la pestaña Previsión), el sistema genera igualmente `numBoxes`
cajas con `netWeight` 0 o negativo, sin ningún aviso, y crea el palet automáticamente
vinculado al pedido (`onCreatingPallet`).

Este es el mismo problema de dominio ya identificado en **GAP-V2-080** (alta manual y por
distribución de peso promedio en `usePalletBoxCreation.ts` permiten peso neto 0/negativo),
pero recurriendo en un tercer flujo de creación de cajas —la creación masiva desde previsión
de pedido— que no está cubierto por el `target_files` de ese GAP. Una caja con peso 0 o
negativo es un dato físicamente imposible en un almacén de congelados (no existe una caja de
pescado con peso cero o negativo) y contamina tanto el histórico de trazabilidad como el
GS1-128 generado para esa caja (ver GAP-V2-109, mismo flujo).

## Objetivo

`handleCreatePalletFromForecast` valida que `quantity` sea estrictamente positiva antes de
generar cajas, con el mismo criterio de validación que se aplique en GAP-V2-080 para
mantener consistencia entre los tres flujos de creación de cajas del módulo.

## Contexto

Depende de la solución elegida en GAP-V2-080 (mismo tipo de validación, para no introducir
un criterio distinto en un tercer sitio). Detectado en la auditoría de dominio de la
Superficie C (vinculación masiva de palets desde el pedido) de la segunda pasada v2 de
`pallets`.

## Solución propuesta

Añadir una validación explícita antes del bucle de generación de cajas: si
`parseFloat(detail.quantity) <= 0` para alguna línea con cajas > 0, excluir esa línea (o
bloquear la creación completa con un mensaje claro, según el criterio que se fije en
GAP-V2-080) y notificar al usuario con `notify.error`/`notify.warning` indicando qué línea de
la previsión tiene cantidad inválida.

## Criterios de aceptación

- [ ] `handleCreatePalletFromForecast` no genera cajas con `netWeight` 0 o negativo.
- [ ] El usuario recibe un aviso claro señalando qué línea de previsión tiene una cantidad
      inválida.
- [ ] Consistente con el criterio de validación aplicado en GAP-V2-080.

## Plan de validación

```text
npm run type-check
npm run lint
Verificación manual: introducir una cantidad 0 o negativa en una línea de previsión con
cajas > 0, intentar "Crear palet desde previsión" y confirmar que el sistema avisa en vez de
crear cajas con peso inválido.
```
