# GAP-V2-068 — Eliminar todas las cajas (desktop) no pide confirmación antes de ejecutar

## Problema

En la pestaña "Eliminar" de `PalletView` (desktop), el botón "Eliminar todas las cajas"
ejecuta la eliminación directamente al hacer clic, sin ningún diálogo de confirmación:

```tsx
// src/components/Admin/Pallets/PalletDialog/PalletView/index.tsx:2601-2609
<Button
  variant="destructive"
  className="w-full"
  onClick={() => handleOnClickDeleteAllBoxes()}
  disabled={isReadOnly}
>
  <Trash2 className="h-4 w-4" /> Eliminar todas las cajas
</Button>
```

`handleOnClickDeleteAllBoxes` (línea ~438-441) llama a `deleteAllBoxes()` sin ningún paso
intermedio. Esto viola directamente `design-context.md` § Modals ("Destructive confirmation
pattern": toda acción destructiva/irreversible debe pasar por `AlertDialog`) y la UX Principle
#1 documentada ("Destructive actions always require confirmation").

El equivalente mobile de la misma acción sí implementa la confirmación correctamente:

```tsx
// src/components/Admin/Pallets/PalletDialog/MobilePalletView/EliminarTab.tsx:87-115
<AlertDialog>
  <AlertDialogTrigger asChild>
    <Button size="lg" variant="destructive" className="h-14 w-full" disabled={boxes.length === 0}>
      <Trash2 className="mr-2 h-5 w-5" />
      Eliminar todas las cajas
    </Button>
  </AlertDialogTrigger>
  <AlertDialogContent>
    <AlertDialogHeader>
      <AlertDialogTitle>¿Eliminar todas las cajas?</AlertDialogTitle>
      <AlertDialogDescription>
        Se eliminarán las {boxes.length} caja{boxes.length !== 1 ? 's' : ''} del palet.
        Esta acción no se puede deshacer una vez guardado.
      </AlertDialogDescription>
    </AlertDialogHeader>
    ...
```

Es decir: la misma acción, sobre la misma entidad, tiene protección en mobile y no la
tiene en desktop — una divergencia de seguridad/UX entre las dos implementaciones del
mismo flujo.

## Objetivo

El botón "Eliminar todas las cajas" en desktop (`PalletView`) exige confirmación explícita
del usuario antes de ejecutar `deleteAllBoxes()`, con el mismo nivel de detalle que la
versión mobile (número de cajas afectadas, aviso de irreversibilidad).

## Contexto

`PalletView` (desktop) y `MobilePalletView` son implementaciones completamente separadas
del mismo flujo de edición de palet (ver nota de scope del audit). El resto de acciones
destructivas de `PalletView` sí usan `AlertDialog` correctamente (eliminar caja individual:
línea 2780-2804; borrar historial: línea 2807-2826) — solo "Eliminar todas las cajas" quedó
sin el patrón.

## Solución propuesta

Añadir un `AlertDialog` de confirmación para "Eliminar todas las cajas" en `PalletView`,
siguiendo el mismo patrón ya usado en el propio archivo para "eliminar caja" y "borrar
historial" (estado `deleteAllBoxesConfirmOpen`, `AlertDialogTrigger asChild` envolviendo el
botón, título y descripción con el número de cajas afectadas — replicar el copy de
`EliminarTab.tsx` en mobile para mantener consistencia de mensaje entre ambas superficies).

## Criterios de aceptación

- [ ] El botón "Eliminar todas las cajas" en desktop abre un `AlertDialog` antes de ejecutar
      `deleteAllBoxes()` — nunca se ejecuta en el `onClick` directo del botón.
- [ ] El `AlertDialogDescription` indica el número de cajas que se eliminarán, igual que en
      mobile (`EliminarTab.tsx`).
- [ ] `AlertDialogAction` usa el estilo destructivo ya establecido en el resto del archivo
      (`bg-destructive text-destructive-foreground hover:bg-destructive/90`).
- [ ] El comportamiento en `isReadOnly` se mantiene (botón deshabilitado, sin cambios).
- [ ] No se modifica ningún otro flujo de eliminación ya confirmado en el archivo.

## Plan de validación

```text
npm run type-check
npm run lint
Verificación manual: abrir un palet con cajas en desktop → pestaña Eliminar → clic en
"Eliminar todas las cajas" → confirmar que aparece el AlertDialog y que cancelar no borra
nada; confirmar que aceptar sí ejecuta el borrado.
```
