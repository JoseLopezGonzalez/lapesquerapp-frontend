# GAP-V2-104 — Falta columna "Posición" en el listado de palets (fusión con GAP-V2-098)

## Problema

**Fusionado en normalización** — mismo hallazgo detectado de forma independiente
por dos carriles distintos de esta segunda pasada:

- **domain-business-auditor (GAP-V2-104):** el filtro `position`
  (`src/configs/entities/entitiesConfig.stock.ts:483-491`) permite filtrar palets
  por "Ubicado" / "No ubicado", pero la tabla resultante (`table.headers`, líneas
  577-636) no muestra en ningún punto el código de posición física dentro del
  almacén (el mismo campo `pallet.position` que sí se usa y muestra en
  `AddElementToPositionDialog/index.tsx:311-316` como badge
  `<MapPin/>{pallet.position}`). Para un operario que filtra "palets ubicados" con
  el objetivo de ir a recogerlos físicamente, el dato que necesita ver en la lista
  es precisamente _dónde_ está cada uno (p.ej. "A1-B2"), no solo que "está
  ubicado". Hoy tiene que abrir cada palet uno a uno (o ir al mapa del almacén en
  `StoresManager`) para averiguar su posición exacta.
- **ui-audit-agent (GAP-V2-098, absorbido aquí):** mismo archivo, mismo ángulo
  desde UX — el filtro "Ubicado/No ubicado" no tiene ninguna columna que confirme
  visualmente el resultado. La única columna relacionada con ubicación es `store`
  (`path: 'store.name'`), que refleja el **almacén**, no la **posición/slot**
  dentro de él — un palet puede pertenecer a un almacén y estar "no ubicado"
  (sin slot asignado). Filtrar por "No ubicado" hoy no se puede verificar
  visualmente en la tabla: la columna `store` puede seguir mostrando un nombre de
  almacén, lo que puede leerse como contradictorio con el filtro si el usuario no
  conoce la distinción interna entre "almacén" y "posición dentro del almacén".

Ambos apuntan al mismo archivo y a la misma solución (añadir columna `position` a
`table.headers`) — es el mismo problema de fondo visto desde el ángulo de negocio
(qué necesita el operario) y desde el ángulo de UX (el filtro no es verificable).

## Objetivo

La tabla de palets muestra una columna "Posición" con el código de ubicación
física (vacío/"–" cuando el palet no está ubicado), de forma que (a) el resultado
del filtro "Ubicado/No ubicado" sea verificable directamente en la tabla sin abrir
el detalle de cada palet, y (b) el operario que filtra "ubicados" para ir a
recogerlos físicamente vea de un vistazo dónde está cada uno.

## Contexto

Detectado de forma independiente en la Superficie A (listado de palets) de la
segunda pasada v2 de `pallets` por domain-business-auditor y por ui-audit-agent
(GAP-V2-098, absorbido en este GAP durante la normalización — ver ese archivo
para el detalle original). Complementa (no depende de) GAP-V2-103, que cubre la
columna de fecha en el mismo `table.headers` — se mantienen como GAPs separados
porque son columnas distintas verificables de forma independiente (GAP-V2-103
además está `blocked` por un dato pendiente de confirmar con Jose, mientras este
GAP no depende de ninguna confirmación externa: el campo `position` ya se usa y
confirma en `AddElementToPositionDialog`).

## Solución propuesta

Añadir un header `{ name: 'position', label: 'Posición', type: 'text', path:
'position' }` (mismo campo ya usado en `AddElementToPositionDialog`, sin
ambigüedad de nombre) junto a la columna `store` ya existente, para que ambas
—almacén + posición— den la localización completa del palet en una sola fila.

## Criterios de aceptación

- [ ] La tabla de palets muestra una columna "Posición" junto a la columna
      "Almacén".
- [ ] Palets sin posición asignada muestran el placeholder estándar ("–") en vez
      de vacío.
- [ ] Filtrar por "No ubicado" muestra resultados cuya columna de posición es
      consistentemente "–"; filtrar por "Ubicado" muestra resultados con un valor
      de posición real — el resultado del filtro es verificable directamente en
      la tabla sin abrir el detalle de cada palet.
- [ ] El filtro "Ubicado/No ubicado" existente sigue funcionando sin cambios.
- [ ] Sin regresión en el resto de columnas/filtros existentes de la config de
      `pallets`.

## Plan de validación

```text
npm run type-check
npm run lint
# Manual: aplicar el filtro "No ubicado" en /admin/pallets y confirmar que la
# nueva columna de posición está vacía/"–" en todos los resultados; aplicar
# "Ubicado" y confirmar que todos tienen un valor real de posición física.
```

## Resultado

Añadido header `{ name: 'position', label: 'Posición', type: 'text', path:
'position' }` junto a la columna "Almacén" en `table.headers`. Mismo campo ya
usado en `AddElementToPositionDialog`. Placeholder "-" automático para palets
sin posición vía `getSafeValue` (patrón ya usado por el resto de columnas
`text`). `npm run type-check` y `npm run lint` limpios.
