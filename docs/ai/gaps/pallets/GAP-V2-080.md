# GAP-V2-080 — Alta manual y por distribución de peso promedio permiten crear cajas con peso neto 0 o negativo

## Problema

`onAddNewBox` (`src/hooks/pallets/usePalletBoxCreation.ts`) valida de forma inconsistente el
peso neto según el método de alta de caja:

**Método `bulk` (masiva) — SÍ valida correctamente:**
```ts
// usePalletBoxCreation.ts:160-166
const weight = parseFloat(cleanLine);
if (isNaN(weight) || weight <= 0) {
  hasError = true;
  return;
}
```

**Método `manual` — NO valida que el peso sea positivo:**
```ts
// usePalletBoxCreation.ts:74-96
if (method === 'manual') {
  if (!productId || !lot || !netWeight) {   // "0" es truthy como string no vacío → pasa el check
    ...
  }
  const newBox = { product, lot, netWeight: roundToTwoDecimals(netWeight), scannedCode };
  addBox(newBox);   // ← crea la caja con netWeight = 0 sin ningún aviso
```

Como `boxCreationData.netWeight` es un string, el check `!netWeight` solo descarta el campo
vacío (`''`); el valor `"0"` es un string no vacío y por tanto pasa la validación como si fuera
un peso válido, generando una caja de 0 kg en el palet.

**Método `average` (promedio) — NO valida que el peso resultante sea positivo:**
```ts
// usePalletBoxCreation.ts:112-118
const palletWeightValue = palletWeight ? parseFloat(palletWeight) : 0;
const boxTareValue = boxTare ? parseFloat(boxTare) : 0;
const totalBoxTare = boxTareValue * parseFloat(numberOfBoxes);
const netTotalWeight = parseFloat(totalWeight) - palletWeightValue - totalBoxTare;
const numberOfBoxesInt = parseInt(numberOfBoxes);
const averageNetWeight = netTotalWeight / numberOfBoxesInt;   // puede ser negativo o cero
```

Si el operario introduce un "Peso Total" menor que la suma del peso del palet + tara total de
cajas (un error de tecleo plausible, p. ej. escribir el peso neto del producto en vez del peso
bruto de báscula), `netTotalWeight` sale negativo y se generan N cajas con `netWeight` negativo
sin ningún aviso — el sistema las crea igual, silenciosamente.

Esto contrasta con `bulkEditBoxes.changeNetWeight` (`usePalletBoxOperations.ts:271-278`), que sí
valida `isNaN(parsedWeight) || parsedWeight <= 0` al **editar** el peso de cajas existentes. Es
decir: el mismo dato de dominio (peso neto de una caja) está protegido en un punto del flujo
(edición masiva) y desprotegido en otros dos (alta manual, alta por promedio) — divergencia de
la misma regla de negocio dentro del mismo módulo.

## Objetivo

Ninguna caja puede crearse (por ningún método de alta) con un peso neto igual o menor que cero.
El sistema avisa al operario en el momento, antes de crear la caja — no permite guardar un
palet con cajas de peso físicamente imposible.

## Contexto

Un peso neto de caja ≤ 0 kg es físicamente imposible y corrompe: el peso neto total del palet
mostrado en resumen/etiqueta/impresión, cualquier cálculo de coste por kg derivado, y los
registros de trazabilidad que se consultan después. Al no haber aviso en el momento de creación,
el error solo se detectaría — si acaso — al revisar el palet ya guardado.

## Solución propuesta

- Método `manual`: cambiar el check `!netWeight` por una validación numérica explícita
  (`parseFloat(netWeight) > 0`), con el mismo mensaje de error ya usado en `bulk`
  ("El peso debe ser un número positivo").
- Método `average`: tras calcular `netTotalWeight`/`averageNetWeight`, validar que sea > 0 antes
  de generar las cajas; si no lo es, mostrar `notify.error` explicando que el peso total
  introducido es menor que el peso del palet + tara de cajas configurados, y no crear ninguna
  caja.
- Revisar si el mismo problema aplica al componente mobile equivalente (`AddManualScreen.tsx`,
  que llama al mismo `onAddNewBox({ method: 'manual' })` — se beneficia automáticamente del fix
  en el hook si se corrige ahí).

## Criterios de aceptación

- [ ] Introducir un peso neto de "0" en el modo manual (desktop o mobile) muestra un error y no
      crea la caja.
- [ ] Introducir en modo "promedio" un peso total menor que peso del palet + tara total de cajas
      muestra un error explicando la causa y no crea ninguna caja.
- [ ] El modo `bulk` (masiva) mantiene su validación existente sin cambios de comportamiento.
- [ ] `bulkEditBoxes.changeNetWeight`/`addOrSubtractWeight` (edición de cajas existentes)
      mantienen su validación existente sin cambios.

## Plan de validación

```text
npm run type-check
npm run lint
Verificación manual: (1) alta manual con peso "0" → debe rechazarse. (2) alta por promedio con
peso total menor que palet+taras → debe rechazarse con mensaje claro. (3) alta masiva con un peso
negativo en una línea → sigue rechazándose como hoy.
```
